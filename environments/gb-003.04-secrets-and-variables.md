# GB-003.04 — Secretos y variables por ambiente

> **Evidencia histórica:** las variables Vercel aquí inventariadas pertenecen a los proyectos iniciales que el autor eliminará manualmente. Sus nombres/ámbitos originales no acreditan presencia ni validez en proyectos futuros. La publicación productiva nueva y la validación local usan [`deployment-policy-local-first.md`](deployment-policy-local-first.md) y [`../tasks/mvp.md`](../tasks/mvp.md); no habrá Vercel Preview.

Registro de la preparación e inventario de variables para Vercel y GitHub
Actions. Este archivo no contiene valores de secretos, tokens, claves privadas
ni URLs de conexión.

## 2. Proyectos Vercel

Los tres proyectos de [GB-003.03](./gb-003.03-vercel.md) se consultaron con la
CLI `vercel` autenticada. AuthUser y Game ahora tienen una variable secreta
`*_DATABASE_URL` en `Production` y `Preview`; Frontend tiene
`IGDB_CLIENT_ID` e `IGDB_CLIENT_SECRET` en `Production` y `Preview`, ambos con
tipo `Secret`.

| Aplicación | Variables publicadas ahora | Variables diferidas hasta que exista código/despliegue |
| --- | --- | --- |
| AuthUser | `AUTH_DATABASE_URL` en `Preview`/`Production`, rol `gamebook_auth_app` | `JWT_PRIVATE_KEY`, `JWT_ISSUER`, `JWT_AUDIENCE`, `CORS_ALLOWED_ORIGINS`. |
| Game | `GAME_DATABASE_URL` en `Preview`/`Production`, rol `gamebook_game_app` | `JWT_PUBLIC_KEY`, `JWT_ISSUER`, `JWT_AUDIENCE`, `AUTHUSER_URL`, `CORS_ALLOWED_ORIGINS`. |
| Frontend | `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` en `Preview`/`Production`, solo servidor | `NEXT_PUBLIC_AUTHUSER_URL`, `NEXT_PUBLIC_GAME_URL`. |

Los valores dependientes del entorno se definirán separadamente para
producción y preview/develop cuando puedan determinarse. Ninguna URL directa
de migración se configura en Vercel.

## 3. Secretos de GitHub Actions previstos

Cada backend tendrá un secreto de ambiente por rama/ambiente, con una URL
directa distinta para `develop` y `production`:

| Repositorio | Secreto | Rol permitido |
| --- | --- | --- |
| `GameBook.Microservice.AuthUser` | `AUTH_DATABASE_DIRECT_URL` | `gamebook_auth_migrator_limited` |
| `GameBook.Microservice.Game` | `GAME_DATABASE_DIRECT_URL` | `gamebook_game_migrator_limited` |

Los secretos `AUTH_DATABASE_DIRECT_URL` y `GAME_DATABASE_DIRECT_URL` ya están
configurados en `develop` y `production` del repositorio backend
correspondiente. Los roles heredados `gamebook_auth_migrator` y
`gamebook_game_migrator`, que conservan privilegios amplios, no se usarán ni se
copiaron a Actions. No se registró ningún valor de conexión en este documento,
terminal o log.

## 4. Evidencia publicada y límite de verificación

1. `gh auth status` fue restaurado y verificado para `CarlosSV923`. Se crearon
   los ambientes GitHub Actions `develop` y `production` en ambos backends y se
   guardaron los cuatro secretos directos de migración limitada; `gh secret
   list` confirmó solo sus nombres y destinos.
2. La prueba local anterior intentó usar `vercel env run` y, después, un archivo temporal
   de `vercel env pull` para `Preview` y `Production`. Vercel bloqueó la lectura
   de las variables `Secret`; el segundo intento no recibió credenciales
   utilizables y produjo HTTP `400`. Ese resultado no diagnostica las
   credenciales reales y no se considera una prueba OAuth válida. Los archivos
   temporales se eliminaron y no se imprimió ningún secreto ni token. **Esta
   prueba ya no forma parte del criterio de cierre de GB-003.04**.
3. Una nueva consulta de nombres con `vercel env ls` confirmó en `Preview` y
   `Production` únicamente `AUTH_DATABASE_URL` para AuthUser,
   `GAME_DATABASE_URL` para Game y `IGDB_CLIENT_ID`/`IGDB_CLIENT_SECRET`
   para Frontend. `gh secret list` confirmó `AUTH_DATABASE_DIRECT_URL` y
   `GAME_DATABASE_DIRECT_URL` en los ambientes `develop` y `production` de
   su backend respectivo. No se leyó ningún valor. **No figuran aún** en
   Vercel `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`, `JWT_ISSUER`, `JWT_AUDIENCE`,
   `CORS_ALLOWED_ORIGINS`, `AUTHUSER_URL`, `NEXT_PUBLIC_AUTHUSER_URL` ni
   `NEXT_PUBLIC_GAME_URL` en sus proyectos/ámbitos correspondientes. Ya no
   forman parte del cierre de esta subtarea: tienen dueño y prueba futura en
   [`gb-003.05-variable-handoff.md`](./gb-003.05-variable-handoff.md).
4. No se generaron claves JWT ni se inventaron credenciales; hacerlo sin una
   decisión y sin un canal seguro de entrega dejaría incompleta la separación
   entre `develop` y `production`.

## 5. Criterio de cierre aplicado

GB-003.04 se resuelve con las seis variables de aplicación/credenciales
**determinables ahora** publicadas en los proyectos y ámbitos correctos:
`AUTH_DATABASE_URL`, `GAME_DATABASE_URL`, `IGDB_CLIENT_ID`,
`IGDB_CLIENT_SECRET`, `AUTH_DATABASE_DIRECT_URL` y
`GAME_DATABASE_DIRECT_URL` (estas dos últimas en ambos ambientes GitHub de
su backend). Se confirmó su presencia mediante `vercel env ls` y `gh secret
list`, sin leer valores. Las pruebas de conexión runtime, migraciones,
obtención/renovación OAuth y JWT quedan pendientes de ejecución del código;
la ausencia de URLs, claves JWT y CORS antes de existir los despliegues no
bloquea este cierre. No se publicaron placeholders ni se afirmó que las
credenciales ya funcionen. El traspaso concreto está en el documento de
`GB-003.05`.
